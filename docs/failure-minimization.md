# Failure reproduction and minimization

A failing schedule directory contains `bundle.json` and readable `events.jsonl`. The JSON is authoritative and self-contained: source events, identity/fingerprint, exact operations, manifest settings, expected normalized state, actual execution observations, differences, tool version, executable SHA-256 when available. It has no live database URL or inherited environment dump. Filenames are generated by the harness, never taken from event IDs or fixture names.

```sh
iro reproduce --bundle reports/buggy/failure-duplicate-delivery
iro minimize --bundle reports/buggy/failure-duplicate-delivery
iro reproduce --bundle reports/buggy/failure-duplicate-delivery/minimized
```

Reproduction validates the fixture fingerprint and operation constraints, uses a new workspace, and executes the recorded schedule rather than the generator. Preserve the recorded consumer executable; a changed executable fingerprint is rejected. The bundle's fixture is independent of the original file. When moving to another machine, place the same executable at the configured command path or edit `manifest.consumer.command[0]` in the bundle to its new location; the binary fingerprint still protects exact reproduction. Recompiling or changing binaries changes the environment and requires a new verification run. PostgreSQL reproduction also requires the configured local test environment variable. The same schedule and binary cannot guarantee deterministic external application behavior; inspect observed outcomes.

The minimizer first confirms stable target reproduction `confirmations` times (default two). It supports `STATE_DIVERGENCE`. Baseline nondeterminism, handler/protocol/environment failures, and golden semantic failures are not reduced; each requires a different failure predicate. In particular the tool will not delete source events under an independently supplied golden oracle it cannot recompute.

Permitted reductions:

1. Remove one source event and every delivery referencing it, unless another remaining event depends on it.
2. Remove one operation, retaining every source's first delivery and its ordering constraints.
3. Turn off an unnecessary crash hook.

For each valid candidate, execute two fresh reduced canonical baselines, reject unstable results, and repeatedly execute the reduced schedule. Only the same stable state-divergence classification is accepted. Event identity is never rebuilt from a processing position. All accepted bundles retain dependency-valid source order and complete schedules.

Results record attempts, original size, confirmations and status. `stable_1_minimal` means a complete pass found no improving _single permitted reduction_, including fault removal; it is not global shortestness. Budget exhaustion gives `stable_budget_limited` and the smallest verified candidate encountered. Configure attempt/time limits in `[testing]`. Initial intermittent or non-reproducible failures are rejected rather than mislabeled stable. Output is written to a new `minimized/` directory and never overwrites an existing reduction.
